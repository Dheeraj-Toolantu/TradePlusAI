NIFTY OPTIONS ALGO STRATEGY V5
MASTER AI IMPLEMENTATION PROMPT PACK
=====================================

PURPOSE
-------
This document is a professional, task-by-task implementation prompt for an AI
coding agent or software development team.

It is based on:
1. NIFTY OPTIONS ALGO STRATEGY — V5 (Merged Specification)
2. Code Review, Validation & Implementation Recommendations
3. The identified deficiencies in the current engine.py and orb.py prototype.

The objective is to transform the existing prototype into a modular,
deterministic, testable, fail-closed, production-grade NIFTY options algo
platform suitable for paper trading first and eventual controlled broker
execution.

IMPORTANT SAFETY / IMPLEMENTATION PRINCIPLES
---------------------------------------------
- Do not connect the implementation to live capital merely because tests pass.
- Do not assume any strategy threshold is profitable; all thresholds are
  configurable and must be backtested.
- Never hard-code lot size, tick size, freeze quantity or expiry weekday.
- Never use unrestricted market orders for normal entry.
- Never bypass risk controls because a signal has a high score.
- Never average down, martingale, revenge trade or auto-re-enter after a broker
  forced exit.
- Fail closed: uncertainty must result in NO_TRADE or SAFE_MODE.
- Keep signal generation, option selection, risk planning and execution
  completely separate.
- Preserve deterministic behavior: identical input data must produce identical
  decisions.
- Every decision must be explainable and auditable.

GLOBAL ACCEPTANCE RULE
----------------------
Do not claim a task is complete unless:
1. The implementation exists.
2. Automated tests exist.
3. Tests pass.
4. Edge cases are covered.
5. No hidden manual override is required.
6. The behavior is deterministic.
7. The implementation is documented.
8. The task's acceptance criteria are explicitly demonstrated.

Do not silently weaken or remove a V5 requirement to make tests pass.

STRICT REPOSITORY STATUS
------------------------
Under the above rule, none of the tasks in this V5 checklist are currently marked
complete because the repository does not yet contain a complete implementation with
passing automated tests for the required V5 behavior. Every task below remains
unchecked until acceptance evidence is present.
